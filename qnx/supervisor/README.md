# Development supervisor

Build with `make supervisor` and run `build/quiver-supervisor [binary-directory]` in the guest. The default directory is `/opt/qnx-quiver/bin`. It starts the PCI manager first, waits for `/dev/quiver`, then starts the split CAN processes, IMU consumer, and trace writer. It restarts exited children with exponential backoff capped at 30 seconds and stops children on SIGINT/SIGTERM.

The IMU consumer is the sole IMU ring consumer in this group. Do not start `quiver-controller` alongside it: ring reads are work-shared rather than fanned out. The trace utility reads telemetry only and does not drain data rings.

This is a development process supervisor. Its children inherit the supervisor's security type, and a missing PCI device causes restart/backoff rather than a product-specific readiness notification. The production image must launch components under separate least-privilege types and add readiness, restart policy, and logging rules to its own service manager. In the disposable QNX guest, readiness, trace-child restart, coordinated SIGTERM shutdown, two fresh cold boots, and PCI-manager-process outage recovery passed. When `/dev/quiver` disappears, the supervisor stops dependent clients; after the manager republishes it, the supervisor launches fresh service instances. PCI-server stop/restart recovery remains unverified on the current QEMU topology.

For the disposable guest test, build `qemu/build_hotplug_test_ifs.ps1 -IncludeServices -SupervisorMode`. This embeds the PCI manager without starting it from boot, so the supervisor can own its lifecycle. Start `/proc/boot/quiver-supervisor /proc/boot`, terminate the trace child, and verify it returns. Terminate the supervisor and verify `/dev/quiver` and all supervised service processes disappear.
